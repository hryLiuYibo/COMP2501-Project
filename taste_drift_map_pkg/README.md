# Listen to the Long Now — Chinese Chart-Listener Behaviour Across Years

Do Chinese mainstream-music listeners *drift* measurably between 2018 and 2024?

We answer it twice, with two independent lenses on the same pipeline:

1. **Chart metadata** — 7 public QQ Music weekly toplists, 2018W30–2024W52
   (~137,000 song-week rows). Changepoint detection, cross-chart correlation,
   genre drift, cross-region structure.
2. **Audio embeddings** — [CLAP](https://arxiv.org/abs/2206.04769) 512-d vectors
   of the 374 charted songs we could obtain as audio. Do the *sounds* of the
   charts drift too, or just the rosters?

This repository is the full, reproducible code and data behind the
presentation. Every figure and every number in the deck is generated from the
CSVs in `r_project/data/` — nothing is hand-typed.

---

## Headline results

| Question | Finding |
|---|---|
| **Q1 — regime shifts?** | Yes. Three changepoints in QQ chart behaviour — **2019, 2020, 2022**, all `p < 0.001` (BIC piecewise-linear fit, k = 3, + 1,000-shuffle permutation test). They line up with the Douyin takeover, COVID-19, and the post-2022 platform split. |
| **Q1 — correlation structure** | Hot Songs ↔ Douyin flips from **+0.32 to −0.76** across the 2022 split. edm grows monotonically (0.27 → 0.41); guofeng declines (0.34 → 0.24). |
| **Q2 — platform-conditional?** | Yes. QQ / NetEase / Apple Music CN / Apple Music US differ in catalogue freshness and star concentration — **Apple Music CN is more "old-catalogue" (84%) and more star-driven (54% top-3) than QQ** (18.9% / 24.5%). So QQ's patterns are platform-conditional, not market-wide. |
| **Q3 — does the audio drift?** | No. Average style is indistinguishable between platforms (full-period centroid angle **3.93°**, inside the 2.6–4.3° bootstrap noise band) and across years (2018→2023 drift **4.14°** is smaller than a single year's swing). Single songs *are* weakly separable (AUC **0.661**, 95% CI [0.591, 0.732]). |
| **Q3 — what actually changes** | The **rosters**, not the average sound. 352 of 374 unique audio files (94%) chart on exactly one platform, yet in CLAP vector space they all mix into one blob. Monthly centroids oscillate up to **23.5°** against the 2018-08 baseline, while yearly centroids barely move. |

Full write-up with all numbers and their provenance: **[`FINDINGS.md`](FINDINGS.md)**.

### 1. Reproduce the figures (no audio needed)

Everything the deck plots is already committed as tidy CSVs, so R is
self-sufficient:

```bash
Rscript r_project/run_all.R          # from anywhere in the repo -> figures/*.png
```

That regenerates all nine figures **and** re-computes the statistics the course
cares about (centroids, same-year angles, single-song AUC + 2,000-fold
bootstrap, centroid-shift bootstrap, coverage). Authoritative values land in
`auc_bootstrap.txt` and `bootstrap_noise.txt`.

> **Verified working from:** the repo root, from inside `r_project/`, from an
> unrelated directory via an absolute path, and as individual scripts
> (`Rscript r_project/04_map_monthly.R`). Scripts self-locate `r_project/`, so
> the working directory does not matter.

### 2. Re-run the audio side (needs the audio)

```bash
# point at the CLAP vectorizer (or clone it next to this repo)
export CLAP_VECTORIZER=~/code/clap-audio-vectorizer     # Windows: set CLAP_VECTORIZER=D:\code\...

cd scripts
python build_matches.py     # charts + audio -> data/interim/charts_matched.csv
python build_vectors.py     # -> vectors.npz, vector_index.csv, per_song.csv
python analyze.py           # -> analysis.json + per-query results
python export_for_r.py      # -> r_project/data/*.csv

cd ../r_project && Rscript run_all.R
```

### 3. Rebuild the deck

```bash
cd scripts
python build_pptx_en.py               # template.pptx + figures/ -> docs/presentation_v3_en.pptx
python build_merged.py                # merge in the metadata deck -> docs/presentation_final.pptx
```

## How a song becomes a vector

The four-step chain drawn in `figures/chain_*.png`, and computed for real on
one probe song (*雪 Distance* by Capper / Luo Yan):

1. **Waveform & windowing** — audio is resampled to 48 kHz mono, then cut into
   non-overlapping **10 s windows** (CLAP's encoder takes fixed-length input).
   A 166 s song → 17 windows.
2. **Log-Mel spectrogram** — linear frequency is warped onto a Mel scale
   (fine at low frequencies, coarse at high — like the ear) and magnitudes are
   logged. The model never sees the waveform again.
3. **Encode & pool** — HTS-AT encodes each window; the 17 window vectors are
   averaged and L2-normalized. One song = **one point on the 512-d unit sphere**.
   Window-to-window cosine averages 0.887, so pooling is safe.
4. **Similarity = angle** — cosine similarity (direction only). Beware the
   **narrow cone effect**: all library songs sit at 0.7–0.9 cosine, not spread
   around 0, so "similarity 0.85" does *not* mean "the same song". Only
   relative differences carry signal.

## Methods, in one screen

**Changepoint detection** (`r_project` / `05_changepoint` logic):
two stages. (1) Fit a k-breakpoint piecewise-linear regression of yearly mean
log-weeks-on-chart against year for k ∈ {0…4}; `BIC = n·log(RSS/n) + (k+3)·log(n)`
selects **k = 3**. (2) Shuffle the yearly means 1,000×, refit k ∈ {0,1,2}, and
compare the minimum BIC — **p < 0.001**.

**Platform difference** — L2-normalized mean vectors ("centroids") per platform
and per year; angle between centroids (degrees). Per-song separability is a
rank statistic: **AUC** over per-song margins `cos(song, QQ centroid) −
cos(song, NE centroid)`, with a 2,000-fold **bootstrap** CI. Centroid-shift
uncertainty comes from a separate bootstrap (300 resamples per year) and gives
the **2.6–4.3° noise band** that all drift claims are measured against.

**PCA, not t-SNE.** The taste map uses PCA because it is linear and globally
distance-preserving — year-to-year distances stay comparable, which t-SNE/UMAP
would distort.

## Data & ethics

- **Only public endpoints are used** for chart data — no login, no API key,
  no scraping behind an account wall.
- **Audio is not redistributed.** We matched chart entries against audio files
  we obtained ourselves; the audio and the raw matched CSVs stay local. What is
  committed is derived numeric data (vectors, centroid coordinates, aggregate
  statistics) plus the code to regenerate it. If you re-run the pipeline you
  must supply your own audio, in keeping with your local copyright rules.
- Coverage is honestly reported and is a stated limitation, not a hidden one:
  QQ 429 entries / 319 songs (58.8%), NetEase 60 / 55 (95.2%), and QQ 2024 H2
  audio is missing — that year's apparent jump is sample collapse and is **not**
  interpreted.
